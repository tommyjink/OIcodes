# C. Toxic Gene 2

这份做法不追求满分查询数，思路是：

1. 先找出一个已经确定是 `T` 的种类。
2. 再把剩下的种类分组，每组只用奇数长度的块来判定。

这样做比更优解多问一些，但很好写，也很好讲。

## 1. 机器的性质

机器每一轮都会删掉这样的样本：

- 当前样本是 `R`
- 并且左右相邻至少有一个是 `T`

删完以后，剩下的样本会重新压成一行，继续下一轮。

所以：

- `T` 永远不会死
- 一整段连续的 `R`，如果两边都是 `T`，就会从两头往中间死

例如：

- `R` 长度为 `1`，死亡过程是 `1`
- `R` 长度为 `3`，死亡过程是 `2,1`
- `R` 长度为 `5`，死亡过程是 `2,2,1`

如果长度是奇数 `2k-1`，那么前 `k-1` 轮每轮死 `2` 个，最后第 `k` 轮死 `1` 个。

这个“最后会单独死一个”的性质，就是这题写成“全奇数块”的关键。

## 2. 怎么判断一堆种类里有没有两种类型

随便拿一个集合 `v`，每个种类只放一个样本。

如果这些样本全同类：

- 全是 `R`，没人挨着 `T`
- 全是 `T`，当然也不会死

所以最后返回的最后一个数一定等于 `v.size()`。

如果里面同时有 `R` 和 `T`，那在某个交界处一定会有一个 `R` 紧挨着 `T`，第一轮就会死人，所以最后存活数一定小于初始长度。

因此可以用这个判断：

```text
query_machine(v).back()==v.size()  <=>  v 里全同类
```

代码里的 `chk(v)` 就是在做这个事。

## 3. 先找出一个确定的 `T`

先固定 `0` 号。

我们想找一个和 `0` 号类型不同的种类 `x`。

把 `1...n-1` 作为候选集合，不断二分：

- 查询 `[0]+候选集合前一半`
- 如果结果混有两类，说明答案在这一半
- 否则答案在另一半

最后会得到一个 `x`，并且它一定和 `0` 类型不同。

接着查询：

```text
[0,x,0]
```

若 `0` 是 `T`，`x` 是 `R`：

- 中间那个 `x` 会死
- 最后剩两个 `0`
- 返回最后结果 `2`

若 `0` 是 `R`，`x` 是 `T`：

- 两边两个 `0` 都会死
- 最后只剩 `x`
- 返回最后结果 `1`

所以：

- 返回 `2`，则 `0` 是 `T`
- 返回 `1`，则 `x` 是 `T`

这样就能得到一个已知的 toxic，记为 `T`。

## 4. 为什么改成“全奇数块”

有了已知的 `T` 以后，就可以把若干未知种类夹在 `T` 中间。

如果块长有奇有偶，虽然能多塞一些人，但解码公式会更绕。

这里我故意不用最优做法，直接把一组写成全奇数长度：

```text
T,
a0,
T,
a1 a1 a1,
T,
a2 a2 a2 a2 a2,
T,
...
```

也就是第 `i` 个种类放 `2i+1` 个。

这样第 `i` 块如果是 `R`，它恰好会在第 `i+1` 轮贡献一个单独的 `1`。

而别的更长奇数块在这一轮只会贡献 `0` 或 `2`，不会影响奇偶性。

于是判断就变得非常简单：

```text
第 i 轮死亡数是奇数  <=>  第 i 块是 R
```

这就是代码里直接写

```cpp
p[v[i]]=(d[i]&1?1:0);
```

的原因。

## 5. 分组具体怎么做

对一组种类 `v[0...k-1]`，构造查询：

```text
T, v0^1, T, v1^3, T, v2^5, T, ...
```

这里 `vi^len` 表示把 `vi` 连续放 `len` 次。

查询返回每轮结束后的存活数，设第 `i` 轮死亡数为 `d[i]`。

那么：

- 若 `d[i]` 是奇数，说明长度为 `2i+1` 的那一块是 `R`
- 若 `d[i]` 是偶数，说明那一块是 `T`

直接就能还原这一组所有种类。

## 6. 为什么每组取 31 个

如果一组放 `k` 个种类，那么总样本数是：

```text
1 + (1+3+5+...+(2k-1)) + k
```

其中：

- 最前面的 `1` 是开头那个 `T`
- 奇数和是 `k^2`
- 每一块后面还要再放一个 `T`，一共 `k` 个

所以总长度是：

```text
k^2+k+1
```

本题一次查询最多放 `1000` 个样本，所以只要满足：

```text
k^2+k+1<=1000
```

取 `k=31` 时：

```text
31^2+31+1=993
```

刚好合法。

所以代码里设每组最多 `31` 个。

## 7. 查询次数

设 `n=1000`。

### 第一步

二分找一个已知 `T`，需要 `O(log n)` 次查询。

### 第二步

每组处理 `31` 个，查询次数约为：

```text
ceil((n-1)/31)
```

总共大概四十多次。

这显然不是最优，但比乱写暴力强很多，也足够拿到大部分分数。
